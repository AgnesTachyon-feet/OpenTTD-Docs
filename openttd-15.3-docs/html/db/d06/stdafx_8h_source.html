189/*
190 * When making a (pure) debug build, the compiler will by default disable
191 * inlining of functions. This has a detrimental effect on the performance of
192 * debug builds, especially when more and more trivial (wrapper) functions get
193 * added to the code base.
194 * Take for example the savegame called "Wentbourne", when running this game
195 * for 100 ticks with the null video driver a number of fairly trivial
196 * functions show up on top. The most common one is the implicit conversion
197 * operator of TileIndex to unsigned int, which takes up over 5% of the total
198 * run time and functionally does absolutely nothing. The remaining functions
199 * for the top 5 are GB, GetTileType, Map::Size and IsTileType to a total of
200 * about 12.5% of the game's total run time.
201 * It is possible to still force inlining in the most commonly used compilers,
202 * but that is at the cost of some problems with debugging due to the forced
203 * inlining. However, the performance benefit can be enormous; when forcing
204 * inlining for the previously mentioned top 5, the debug build ran about 15%
205 * quicker.
206 * The following debug_inline attribute may be added to functions comply
207 * with the following preconditions:
208 * 1: the function takes more than 0.5% of a profiled debug runtime
209 * 2: the function does not modify the game state
210 * 3: the function does not contain selection or iteration statements,
211 * i.e. no if, switch, for, do, while, etcetera.
212 * 4: the function is one line of code, excluding assertions.
213 * 5: the function is defined in a header file.
214 * The debug_inline attribute must be placed in front of the function, i.e.
215 * before the optional static or constexpr modifier.
216 */
217#if !defined(_DEBUG) || defined(NO_DEBUG_INLINE)
218/*
219 * Do not force inlining when not in debug. This way we do not work against
220 * any carefully designed compiler optimizations.
221 */
222#define debug_inline
223#elif defined(__clang__) || defined(__GNUC__)
224#define debug_inline gnu::always_inline
225#else
226/*
227 * MSVC explicitly disables inlining, even forced inlining, in debug builds
228 * so __forceinline makes no difference compared to inline. Other unknown
229 * compilers can also just fallback to a normal inline.
230 */
231#define debug_inline
232#endif
